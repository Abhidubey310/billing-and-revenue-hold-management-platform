# Portfolio Story

## 60-second explanation

I designed a billing and revenue hold management prototype to address a common finance-operations problem: held orders are often reviewed manually, ownership is unclear, and teams lack a consistent view of ageing and financial exposure.

The solution validates synthetic held-order data, classifies each case into a standard hold category, assigns an accountable team, calculates priority using ageing and value, and produces an auditable recommendation. I deliberately used explainable rules so a business user can understand why each decision was made.

The project demonstrates how I translate a finance-control problem into a structured automation solution while keeping human review for exceptions and accounting-sensitive decisions.

## STAR structure

**Situation:** Billing holds can delay invoicing and create weak visibility of revenue exposure.

**Task:** Design a scalable way to classify cases, assign ownership, and prioritise action.

**Action:** Created synthetic data, defined generic rules, built a Python engine, added validation, and produced explainable outputs.

**Result:** A reusable prototype that demonstrates faster triage, clearer accountability, stronger governance, and improved management visibility.
